# Gold Coast Build

Marketing site for Gold Coast Build, a Chicago residential and commercial
construction company.

A static site generated by Python. No framework, no Node, no runtime, no
database — `build.py` renders the HTML and resizes the photographs, and the
output in `dist/` is plain files that any static host will serve.

| | |
|---|---|
| Runtime | Python 3.8+ |
| Dependencies | Pillow — the only one |
| Output | 16 HTML pages, 124 image files |
| Build time | ~11s cold, ~2s warm |
| Hosting | Vercel (see [DEPLOY.md](DEPLOY.md)) |

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python build.py                  # render into dist/
python verify.py                 # gate: must print "all checks passed"

cd dist && python -m http.server 8777
```

Then open <http://127.0.0.1:8777>.

## How it works

Python runs at **build time only**. Nothing in `dist/` is Python; the
deployed site is HTML, CSS, JS and images. It fills the role Jekyll or Hugo
would, hand-rolled for this site, and does four jobs:

**Templating** — one `shell()` function owns the `<head>`, header, nav and
footer for all 16 pages, so a change to the phone number is one edit.

**Repetition** — the seven project pages come from a single loop over
`content.json`. Adding a project produces its page, its gallery, its cards
on the home and projects pages, and its sitemap entry.

**Image processing** — each referenced photograph is resized to 480 / 768 /
1200 / 1800px and emitted with `srcset` and a `sizes` hint, so a phone
downloads roughly 200 KB instead of 3.2 MB. Real pixel dimensions are read
from every file and written as `width`/`height`, which is what stops the
layout shifting as images load.

**Derived files** — `sitemap.xml`, `robots.txt`, canonical tags, Open Graph
image and the favicons are all computed from the same page list the HTML
came from, so they cannot drift out of sync.

## Layout

```
build.py          page composition, <head> metadata, schema, sitemap, robots
editorial.py      the long-form copy blocks and the FAQ pairs
photography.py    image curation, responsive variants, <img> markup
content.json      project paths and their source photograph lists
verify.py         post-build checks; exits non-zero on failure
src/style.css     mobile-first stylesheet  (copied to dist/ verbatim)
src/app.js        progressive enhancement  (copied to dist/ verbatim)
src/assets/       original photographs — the source of truth
vercel.json       build config, security headers, cache policy, redirects
dist/             generated output; safe to delete at any time
```

`dist/` is disposable and git-ignored. `rm -rf dist && python build.py`
always reproduces the site byte for byte. **Never edit anything inside
`dist/`** — edit `src/` and rebuild.

## Making changes

Copy lives in `editorial.py`, `build.py` and `content.json`; photographs in
`src/assets/`.

```bash
python build.py && python verify.py
git commit -am "..." && git push
```

Push to `main` deploys to production. Open a pull request instead and Vercel
builds a preview URL first.

### Adding a photograph

Put the file in `src/assets/`, reference it from `content.json`, and add it
to the relevant entry in `photography.SELECTIONS`. Photographs that are not
selected are never copied into `dist/` — that is deliberate, the unselected
files are the curation pool.

### Editing the stylesheet

`src/style.css` is mobile-first: rules outside any media query describe the
phone layout, and `min-width` queries add tablet (761px), desktop (1051px)
and wide (1700px) on top. There are also two `max-height` tiers that
compress the hero on short viewports.

Add new rules in that structure rather than appending an override block at
the end. The previous version of this stylesheet had grown to eight stacked
override layers with 105 selectors each defined more than once.

## Verification

`verify.py` is the gate, and CI runs it on every push:

- every internal link and every `srcset` candidate resolves
- exactly one `<h1>` per page, `alt` on every image, no duplicate ids
- canonical, Open Graph, Twitter and JSON-LD present and parsing
- no `target="_blank"` without `rel="noopener"`
- JSON-LD contains no unescaped `<` that could close its own `<script>`
- the sitemap lists only pages that were actually built

CI also builds twice and diffs the output, so a non-reproducible build
fails.

## Deployment

See **[DEPLOY.md](DEPLOY.md)** — the full runbook, including the Squarespace
to Vercel migration and the Cloudflare DNS cutover.

The production domain is set in one place: `SITE` at the top of `build.py`.
It feeds the canonical tags, Open Graph URLs, `robots.txt` and
`sitemap.xml`.

## Security

See **[SECURITY.md](SECURITY.md)**. In short: the site is static with no
forms, no user input, no cookies and no server-side code, so the attack
surface is small. Security headers ship in `vercel.json`.
